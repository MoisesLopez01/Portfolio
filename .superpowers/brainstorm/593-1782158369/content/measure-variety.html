How should we measure "context variety"?

The Tempo "Key" column tells us which projects each person is planned on each week. Before we display anything, we need to agree what number captures "context-switching load." Here's a concrete week for two rocketeers:

Ana spreads 40h evenly across 4 projects. Ben puts 38h on one project and just 2h on a second — technically "2 projects," but barely switching. How we count this changes the whole story.

Which definition should drive the metric?

A

Distinct project count

Simply how many projects with planned hours that week. Ana = 4, Ben = 2. Dead simple and transparent — matches the dashboard's plain-number style — but treats Ben's 2h sliver as a full context switch.

B

Thresholded count (recommended)

Count only projects above a minimum share (e.g. ≥10% of the week, or ≥4h). Ana = 4, Ben = 1. Stays a clean whole number, but ignores slivers so it reflects real switching. Threshold is tunable.

C

Effective projects (concentration index)

A fractional "effective number of projects" from how evenly hours split (inverse-Herfindahl / entropy). Ana ≈ 4.0, Ben ≈ 1.1. Most faithful to true fragmentation, but a decimal index is harder to explain at a glance.
